# Glossary

**Actor** — A person, organization, system, hardware, or software with behavior (Ch 4).

**Actor-goal list** — A low-precision list of primary actors and the goals the system supports; use it to define functional scope and prioritize work (Ch 3).

**Black-box use case** — A use case that treats the system under discussion as indivisible and does not describe internal components (Ch 3–4).

**Design scope** — The named enterprise, system, or subsystem whose behavior is being described (Ch 3).

**Extension** — A conditional scenario fragment that diverges from a main success step and returns, succeeds separately, or fails (Ch 8).

**Goal level** — The altitude of an actor goal: summary, user-goal, or subfunction (Ch 5).

**Main success scenario (MSS)** — The straightforward, expected path by which the primary actor's goal succeeds (Ch 7).

**Minimal guarantee** — What the system preserves for stakeholders on every exit, including failure (Ch 6).

**Off-stage stakeholder** — A stakeholder affected by the behavior but not necessarily visible in the action steps (Ch 2, Ch 4).

**Primary actor** — The stakeholder that calls on the system to achieve a goal (Ch 4).

**Scenario** — One path of steps, under particular conditions, ending in goal success or failure (Ch 2, Ch 7).

**Stakeholder** — Anyone or anything with a vested interest in the use case's behavior (Ch 2, Ch 4).

**Sub-use case** — A named, expandable goal used as a step in another scenario; it exposes only success or failure to its caller (Ch 10).

**Supporting actor** — An external actor that provides a service to the system under discussion (Ch 4).

**Success guarantee** — The promised resulting state when the primary actor's goal succeeds (Ch 6).

**System under discussion (SuD)** — The scope-bound system whose behavioral contract the use case specifies (Ch 2).

**Technology and data variation** — A different channel or data form for achieving the same behavior; not an alternate behavior (Ch 9).

**Usage narrative** — A short, concrete story of a particular person using the system; it helps discovery but is not itself the formal requirement (Ch 1).

**User-goal** — A meaningful, one-sitting goal at “sea level”; the preferred level for most system use cases (Ch 5).
