# Chapter 20: Each Use Case

## Core Idea

Use a compact review routine for every use case: make its boundary, actor goal, contract, and scenario structure immediately visible.

## Per-Use-Case Checklist

1. Name the goal as a short active verb phrase.
2. State design scope and goal level.
3. Name the primary actor and all material stakeholder interests.
4. State precondition, trigger, minimal guarantee, and success guarantee.
5. Write a short, goal-oriented MSS.
6. Find meaningful extensions and name each outcome.
7. Put channel/data alternatives in variations, not behavior branches.
8. Link related rules, data, and sub-use cases.

## Key Takeaways

1. The checklist prevents familiar omissions without requiring maximal ceremony.
2. A short readable use case can be effective when its contract is clear.
3. Review for purpose, not for document volume.
