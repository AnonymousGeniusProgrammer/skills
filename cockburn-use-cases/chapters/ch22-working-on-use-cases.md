# Chapter 22: Working on the Use Cases

## Core Idea

Use cases work best as a collaborative, iterative writing practice: discover goals, draft quickly, review with domain experts, and refine where uncertainty or value demands it.

## Frameworks Introduced

- **Dive-and-surface**: alternate broad model revision with detailed exploration of one use case.
  - When to use: new or changing domains.
  - How: draft the high-level model, dive into a representative scenario and its alternatives, then return to revise scope and goals.
- **Readability-first collaboration**: favor artifacts people can actually discuss over elaborate diagrams or tool conventions.
  - When to use: cross-functional requirements work.
  - How: use simple text, active steps, shared review, and only as much notation as readers need.

## Key Takeaways

1. Requirements discovery changes the model; expect revision.
2. Domain experts and technical staff contribute different indispensable knowledge.
3. Tools are secondary to clear thinking and readable communication.
